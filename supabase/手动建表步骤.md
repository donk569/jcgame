## 步骤 1 · 打开 SQL 编辑器

浏览器打开这个地址（直接进项目的 SQL Editor）：

```
https://supabase.com/dashboard/project/hvnfewrdzvhpazfwducc/sql
```

登录后左侧应该看到 **SQL Editor**，点它 → 右上角 **New query**。

## 步骤 2 · 执行建表脚本（表结构 + 权限）

打开本地文件（任选一种方式打开）：

```
D:\gameshare\supabase\schema.sql
```

> 用 VS Code 打开：`Ctrl+O` → 粘贴路径 → 回车；然后 `Ctrl+A` 全选、`Ctrl+C` 复制。
> 或者用记事本打开也一样。

回到 Supabase 的 SQL Editor，**粘贴**（`Ctrl+V`），然后：

- 右下角点 **Run**（或按 `Ctrl+Enter`）
- 等待几秒，看到 **Success. No rows returned** 之类的提示就对了

**如果报错**：把完整错误信息发我，我改脚本。脚本可以重复执行（每条策略都先 drop 再 create），报错后修完再跑一遍就行。

**确认建好了**：左侧 **Table Editor**（表图标）里应该出现这 7 张表：

```
creators    comments    drafts    games    profiles    follows    user_games
```

## 遇到问题怎么办

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `relation "public.games" already exists` | 表已建过 | 正常，继续下一步；或直接跑 seed |
| `policy ... already exists` | 策略已存在 | 脚本已改成先 drop，正常 |
| `syntax error at or near ...` | 粘贴时少了内容 | 重新 `Ctrl+A` `Ctrl+C` 完整复制 |
| Run 按钮灰色 / 页面卡 | Dashboard 加载慢 | 刷新页面，或把 SQL 分两次跑（先 schema 后 seed） |
| 权限错误 | 用错了 project | 确认地址里的 ref 是 `hvnfewrdzvhpazfwducc` |

## 附：一条命令验证（你也可以自己跑）

如果你想自己确认，在项目目录执行：

```bash
K=$(grep VITE_SERVICE_ROLE_KEY .env.local | cut -d= -f2)
curl -s -x http://127.0.0.1:7897 \
  -H "apikey: $K" -H "Authorization: Bearer $K" \
  "https://hvnfewrdzvhpazfwducc.supabase.co/rest/v1/games?select=slug&limit=3"
```

能返回游戏 slug 就说明表建好了。（`7897` 是你本机代理端口，若不开代理可以去掉 `-x` 参数，
但国内直连 Supabase 会被重置，所以可能需要开着代理。）
